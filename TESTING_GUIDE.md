# Pine — Testing Guide

> Version 1.0 · Updated 2026-09-23 · Every acceptance criterion in PRD.md has a `T-Fxx-ACn` row in §6. Status values: `planned`, `implemented`, `green`, `blocked`.

## 1. Strategy

Pine's core promise — *no unsupported claims* — is only believable if the invariants are tested, so tests are the product spec made executable.

- **Unit tests** for pure logic: parsers, chunker, extractors, period parsing, contradiction rules, EvidenceGate, derivations. Fast, deterministic, no I/O beyond fixtures.
- **Integration tests** over FastAPI `TestClient` + in-memory SQLite (StaticPool): every endpoint in ARCHITECTURE §5, auth, envelope, pagination, upload pipeline.
- **Invariant tests**: `tests/facts/test_invariants.py` proves no Fact/Entity/Claim can be persisted without evidence; `tests/graph/` proves entity resolution merges correctly.
- **Property tests** (hypothesis) for parsers/normalisers where input space is large (periods, numbers, upload fuzz in P6).
- **Evals** (`pine eval demo`, `pine eval evidence`) are tests: blocking thresholds in EVAL_GUARDRAILS §7.
- **E2E** (Playwright) for the user journeys J1–J4; component tests (Vitest + Testing Library) for complex UI (viewer, grid, drawer).
- **Determinism**: `LLM_PROVIDER=fake`, `EMBEDDINGS_PROVIDER=hash` in all tests — zero network. Anything seeded gets a fixed seed.

## 2. Setup

```bash
make install                      # uv sync + pnpm install
uv run --directory api pytest -q  # sanity
```

Test environment is configured in `api/tests/conftest.py`: in-memory SQLite engine (StaticPool), `get_session` dependency overridden, `PINE_API_KEY` cleared, `get_settings.cache_clear()`. Tests that need a configured key set it via `monkeypatch.setenv` then `get_settings.cache_clear()` (see `tests/test_auth.py`).

Optional extras: `uv sync --directory api --extra ocr` for OCR tests (skipped automatically when the tesseract binary is absent; CI installs it).

## 3. Commands

```bash
make test                                # api suite, quiet
uv run --directory api pytest -q tests/api/test_deals.py      # one file
uv run --directory api pytest -q -k "T-F01"                   # by AC tag
uv run --directory api pytest --cov=pine --cov-report=term-missing
uv run --directory api pytest -q tests/ingest/test_ocr.py     # needs ocr extra
pnpm -C web test                         # vitest (P2+)
pnpm -C web exec playwright test         # e2e (P1+)
uv run --directory api pine eval demo    # blocking evals (P3+)
uv run --directory api pine eval evidence
uv run --directory api alembic upgrade head
```

## 4. Mock Data & Fixtures

| Fixture | Location | Purpose |
|---|---|---|
| Small real documents | `api/tests/fixtures/docs/` | `table_5x4.pdf`, `scanned_page.pdf`, `two_sheets.xlsx`, `broken.pdf`, `with_attachment.eml`, `simple.docx`, `slides.pptx` — built once, committed, tiny |
| FakeLLM scripts | `api/tests/fixtures/llm/*.yaml` | Scripted responses keyed by `purpose` + regex on last user message (ARCHITECTURE §10) |
| Demo data room | `fixtures/northwind/` | Synthetic Northwind SaaS room with planted contradictions; built by `pine demo build` (P1.T14) |
| Demo ground truth | `fixtures/northwind/ground_truth.json` | Expected facts + planted contradictions; validated against its schema (F-14.AC1) |

Rules: fixtures are generated by checked-in scripts where possible; binary fixtures are minimal (one page, few rows); FakeLLM fixtures must be updated when prompts change (EVAL_GUARDRAILS §9).

**Time control:** use a fixed clock via `time-machine` (freezegun-style) — add it as a dev dependency *when first needed*, not before. Until then, inject `now`/`clock` parameters into time-dependent code (worker `run_after`, `run.started_at`) rather than sleeping.

**No sleeps in tests.** The worker exposes `run_once()`; SSE tested via TestClient streams; polling loops driven manually.

## 7. Expected Results

- `make test` exits 0 with all implemented rows green; `planned` rows are absent until their phase.
- Coverage floors (EVAL_GUARDRAILS §7): ≥ 85 % lines on `pine/facts/`, `pine/contradictions/`, `pine/agents/gate.py`; ≥ 70 % overall — enforced from P3.
- Performance assertions are tests: F-07.AC4 (< 60 s fake run), F-01 upload (< 10 s / 100 files), search p95 < 300 ms on demo room.
- Evals: `pine eval demo` prints recall numbers and exits non-zero below thresholds; `pine eval evidence` must print `coverage = 1.0`.

## 8. Verification Loop for Agents

1. Before coding: read the task's ACs and the target test file path — write/extend the test first where practical.
2. Run the narrowest command that covers the change (single test file), then `make test`, then `make lint`.
3. After an API shape change: `make generate && git diff --exit-code web/src/lib/api/types.ts`.
4. Do not mark a task done until its `verify:` command is green and §6 rows it covers are `green`.
5. Two failed attempts on the same failure → stop, record diagnosis in TASK_LOG blockers, escalate (INSTRUCTIONS §12).
6. Never weaken a test, threshold, or guardrail to make something pass.

## 9. CI Pipeline

`.github/workflows/ci.yml` jobs (all required for merge):

- **api**: `uv sync` → `ruff check` → `mypy pine tests` → `pytest -q` (with coverage from P3) → `pine eval demo --fake` (from P6).
- **web**: `pnpm install` → `lint` → vitest (from P2) → `pnpm build` → OpenAPI drift check (`make generate` + `git diff --exit-code`).
- **e2e** (P1+): api with fake providers + web + Playwright.
- **postgres matrix** (P6.T6): api suite against Postgres 16.

CI environment: SQLite in-memory, `LLM_PROVIDER=fake`, `EMBEDDINGS_PROVIDER=hash`, `OCR_ENABLED=false` (tesseract installed for the OCR test), no secrets.

## 10. Manual QA Checklist

Run before each phase exit (full pass at P6):

- [ ] `make install && make api && make web` from a clean checkout works per README.
- [ ] Load demo data room end-to-end via UI; every document reaches `parsed` (or `unsupported` with reason).
- [ ] Overview shows contested badges; clicking through reaches the fact with evidence.
- [ ] Citation chip → viewer opens at the right page with the span highlighted.
- [ ] Resolve a contradiction → overview and memo reflect the authoritative fact.
- [ ] Kill the api mid-run → restart → queued jobs resume; run status is honest.
- [ ] Every route checked in light + dark mode; `prefers-reduced-motion` on; keyboard-only pass (nav, dialog, drawer, viewer).
- [ ] API down → every route shows error + retry, no blank screens (F-13.AC3).
- [ ] `pnpm -C web build` — overview route JS ≤ 300 kB gz.
- [ ] Logs are JSON with `request_id`, no secrets, no account numbers.
